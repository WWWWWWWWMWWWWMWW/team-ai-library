# 证据驱动调试与验证门禁

## 解决什么问题

把失败现象拆成证据链，区分确认、观察、推断和待验证项，完成最小修复并逐层验证。

## 适用与不适用

- 输入：证据、相关源码或配置、当前失败现象
- 输出：定位结论、最小改动、回归结果、未验证项
- 适用范围：跨模块 bug 定位、运行时问题追踪、发布前检查
- 不适用范围：无运行证据直接下结论、未经授权扩大修改范围
- 工具要求：Codex、filesystem.read、filesystem.write
- 副作用与任务权限：read_only、local_generate、project_write；远程写入与发布需单独授权。

## 怎么复用

阅读 `payload/instructions.md`，按准备、证据整理、执行、验证、报告顺序运行；每次使用都记录实际环境和未验证项。

## 依赖

无团队能力依赖；外部工具和业务项目按当前任务现场核对，不自动安装。

## 示例与判断依据

使用团队内部合成任务按流程走一遍，检查输入、步骤、产物、证据和失败处理是否完整。本次只验证材料结构和出站范围，业务效果未验证。

## 已知限制

历史案例中的具体项目规则、路径和版本不能自动外推到其他项目；需要当前源码、配置和运行时证据时，必须重新检查。
