# MergeClient 活动 UI 风格画像

本画像来自 `活动截图.xlsx` 的只读审计：活动截图 444 张、43 类活动；工作簿全部图片引用 538 个、不同二进制图片 535 张、完全重复引用 3 个。截图中混有入口小图、完整页面、规则/领奖弹窗、棋盘内嵌区和礼包页，因此只有经筛选的完整活动页可作为主结构参考。

## 已确认：稳定视觉语言

- **画布与构图**：手机竖屏为主，常见页面接近 9:16。核心内容在中轴内组织，顶部主题区、中部核心玩法/状态区、底部进度奖励与 CTA 形成清晰纵向层级。
- **气质**：轻松、明亮、亲和的 2D 手绘卡通。角色和道具采用胖圆比例、粗轮廓、柔和体积感和夸张但易懂的动作。
- **主题包装**：每个活动有独立主题插画与主题色，但共享奶油白内容面板、暖色木质/纸张质感、深棕正文、鲜明主按钮等系统骨架。
- **面板**：大圆角矩形、浅奶油底、粗彩色描边、柔和投影。标题常嵌在飘带、木牌或主题化顶框中。
- **按钮**：主操作常用高饱和黄绿色；领奖、继续或次级操作可用橙黄。按钮为圆角胶囊或短矩形，带深色描边和轻微高光。
- **关闭与帮助**：关闭按钮常位于右上角，为红色圆形白叉；帮助/说明多在左上或标题附近，以蓝色圆形图标出现。
- **文字**：标题粗圆、白色或浅色字配深色描边；正文深棕，数值和倒计时以图标、色块或小徽章增强。不要依赖纯色区分重要状态。
- **奖励与进度**：奖励图标大于说明文字，常用分段进度条、节点、宝箱、竖向关卡轨道或横向里程碑。当前目标需要在一眼内被识别。
- **背景**：活动主页面常覆盖在棋盘/主场景之上，背景适度压暗；全屏小游戏则使用主题场景填满画布。

## 已确认：常见页面骨架

```text
┌────────────────────────┐
│ 帮助   主题标题/倒计时   关闭 │
│      主题插画或核心状态      │
├────────────────────────┤
│ 玩法目标 / 对手 / 当前进度    │
│ 核心交互、地图、棋盘或任务列表 │
│ 奖励轨道 / 排名 / 商店入口     │
├────────────────────────┤
│ 次要入口       主 CTA         │
└────────────────────────┘
```

并非每页都要同时出现所有区域。一个页面只保留支持当前核心行为的组件。

## 建议：概念图生成约束

- 先沿用系统骨架，再让主题插画、顶框和背景承担差异化，避免每次重造整套组件语言。
- 主 CTA 在首屏内可见，重要状态同时使用文字、图标或形状编码。
- 视觉焦点不超过 3 层：主题/玩法焦点、当前目标、主 CTA。
- 小字仅用于补充说明；概念图里宁可减少信息，也不要生成大段难以辨认的伪文字。
- 若用户未提供业务文案，使用 `活动标题`、`活动说明`、`奖励`、`前往` 等显式占位符，不自行生成数值。

## 禁止误学

- 入口小图只可参考主题图标，不能当页面布局模板。
- 规则、确认、奖励弹窗只可参考组件样式，不能替代主活动页。
- 礼包页和系统功能页不属于本 Skill 的主参考域。
- 截图中的鼠标指针、版本号、黑边、压暗遮罩、裁切和录屏残留不是设计语言。
