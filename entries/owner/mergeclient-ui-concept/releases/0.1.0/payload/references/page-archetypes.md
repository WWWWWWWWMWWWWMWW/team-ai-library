# 活动页面原型

先按玩家在该页的首要行为选择一个主原型。可借用其他原型的局部组件，但不要把多个完整骨架叠在一起。

## 1. 活动引导 / 开场页 `landing`

适合首次进入、主题介绍、报名或开始挑战。上半屏以主题插画为焦点，下半屏用一句目标说明、关键奖励预览和单一主 CTA 收口。

检索词：开始、报名、活动介绍、主题插画、首次进入。

## 2. 任务冲刺 / 订单进度 `objective`

适合完成订单、收集指定物、短周期冲刺。结构是当前目标 + 进度 + 节点奖励 + 前往/领取；可附小型商店入口。

检索词：冲刺、订单、收集、进度、任务、7日。

## 3. 通行证 / 奖励轨道 `pass`

适合连续成长与付费/免费双轨奖励。突出当前等级、升级资源、奖励轨道和解锁状态；避免同时放入完整小游戏棋盘。

检索词：pass、通行证、赛季、等级、奖励轨道。

## 4. 竞赛 / 排行榜 `competition`

适合 1v1、2v2、段位、赛跑和排名。首屏必须让玩家看清对手/队伍、当前名次或双方进度、剩余时间和参与按钮。

检索词：排行、赛跑、对战、1v1、2v2、段位、合作。

## 5. 主题小游戏 `minigame`

适合弹珠、拧螺丝、挖宝、爬塔、开箱等独立玩法。核心交互区占最大面积，进度与奖励围绕它服务；商店和规则退居二级。

检索词：弹珠、棋盘、挑战、挖宝、爬塔、开箱、冒险。

## 6. 收集册 / 棋盘 / Bingo `collection`

适合集齐套组、翻格、相册、Bingo。使用规则化网格、明确的已获得/未获得状态、套组奖励与当前缺口。

检索词：相册、收集、bingo、棋盘、勋章、套组。

## 7. 地图闯关 / 岛屿探索 `map`

适合浮空岛、梦幻岛、丛林冒险等章节式活动。用路径、节点和场景插画承担叙事，保持当前节点、下一目标和能量消耗清楚。

检索词：岛、冒险、地图、闯关、章节、路径。

## 8. 活动商店 / 兑换 `shop`

只有用户明确要求活动商店主页面时使用。采用整齐商品网格、货币余额、限购状态和刷新/兑换反馈；不要让商品卡遮蔽主题身份。

检索词：商店、兑换、刷新、限购。

## 支持性页面

规则、奖励预览、确认、结算和结束页是支持状态。除非用户明确要求，否则概念图的主交付应是上述八类之一，而不是一个弹窗。
