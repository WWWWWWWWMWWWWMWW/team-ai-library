# 本地能力全面盘点与整理

供 AI 读取的执行细则。用户说“全面盘点”“整理全部可沉淀内容”时使用；不是只列文件，也不是自动上传全部材料。策划入口见 [全面整理提示词](LOCAL_CAPTURE_PROMPT.md)。根 AGENTS.md 与 [AI 自动操作手册](AI_OPERATIONS.md) 的权限、中文说明、版本和审核规则继续适用。

## 1. 明确范围并建立完整清单

- 优先使用用户明确指定的项目、文件夹或成果集合。仅上下文明确的当前业务项目可作为默认范围，能力库的接入/克隆目录不能自动视作待盘点业务项目。多个目录分别记录根路径，不扩大到整台机器、其他项目、个人聊天或账号配置。
- 用户未给路径时，先从当前会话已提供的工作区、IDE 项目信息和明确工作目录识别候选；只在这些已知目录内列出必要的一级项目名称与用途，不全盘搜寻或读取未选择项目的内容。范围已明确就直接开始；仍有多个候选时列成中文编号选项，让用户回复项目名称、编号或“以上全部”，不要首先要求用户手写完整路径。没有任何可识别候选时，才请用户指向或选择一个文件夹。
- 将当前范围记录在本地；递归列出文件，并记录相对来源、类型、大小、摘要（适用时）和检查状态。先登记完整清单，再深入检查；隐藏目录按用途处理，用户明确选择的 Skill 目录可以检查，凭据、个人设置、.git 内部对象等不因隐藏与否而纳入。
- 目录清单中记录排除的路径模式和原因：第三方依赖、构建缓存、重复生成文件等可排除。必要的代表产物或结果样例不能仅因“生成文件”一律丢弃；只纳入明确范围内、能解释复用方法的最小脱敏样例。
- 不跟随越界符号链接；压缩包先检查条目和解压路径安全，在独立本地目录受控展开，无法核实则登记未检查。不运行被盘点材料的脚本、hook 或宏。
- 用可用的文档、表格、PDF 或图片读取工具检查实际内容。不能处理的文件登记“不可读取/未检查”和原因；同一文件仅部分页、工作表或图片检查过时标明覆盖范围，不把抽查算完整检查。
- 目录本身无法枚举时记录该目录和阻断原因，标明其文件数量未知；不凭估计补数，也不把能列出的文件数当成原范围全部文件数。
- 对明确项目范围内的变更，可只读查看当前修改及相关 Git 记录，用来解释方法演变；默认不遍历全部历史对象，也不把提交描述当执行或成功证据。需要扩大历史或读取对话记录时，须有对应范围授权。

## 2. 从材料提炼能力，不只找 Skill

| 候选内容 | 看什么原始材料 | 可沉淀成什么 |
|---|---|---|
| 技能与提示词 | Skill 说明、提示词、输入输出示例 | 适用条件清楚的技能/提示词 |
| 多步骤工作方法 | 任务说明、操作步骤、脚本调用、成果文件 | 包含准备、步骤、检查和异常处理的工作流 |
| 自动化与资源处理 | 脚本、转换规则、批处理配置、模板 | 工具或工作流，写明运行前提和副作用 |
| 策划与配置方法 | 业务文档、表格、字段解释、校验清单 | 模板、检查方法、配置流程 |
| 诊断与修复经验 | 排错记录、改动、验证证据、失败材料 | 问题定位方法、脱敏案例或经验 |
| 数据分析与资料研究 | 分析脚本、指标口径、来源、研究过程 | 可复现的分析/研究方法 |
| 成功与失败案例 | 实际任务、产物、过程、结果证据 | 案例、注意事项、失败复盘 |
| 隐性步骤与协作经验 | 前后产物关系、遗漏条件、手动补救 | 前置检查、交接清单和限制说明 |

以上是业务分类，不虚构 CLI 或 schema 类型。生成正式投稿包时映射到当前支持的类型；无法直接对应的内容先保留说明草稿。

- 文件名、扩展名与提交消息只是线索。能力必须有实际内容和来源支持；一个文件可支持多个能力，一个能力也可包含多个文件。
- 通用方法与项目专用部分分别说明，例如“活动配置检查方法”与“该项目表名/字段/地区规则”。不能把一个项目的适用范围外推到所有游戏。
- 实际成果仅作为最小样例；不把整个项目源码、业务表、资源库或聊天归为能力包。需要业务敏感材料才能解释的方法先脱敏，无法判断分享边界则暂不共享。
- 保留真实依赖链：入口、脚本、模板、配套文件、工具版本、环境、权限与外部接口。只抽出主脚本导致缺依赖，不算完整能力。

## 3. 去重、版本与优先级

- 完全相同的材料按摘要聚合来源，不删除原件；内容相近的版本比较用途、步骤、适用范围和结果。不要按名称相同就合并，也不要按名称不同就重复入库。
- 同一完整流程保持一个条目；只有独立输入输出、独立复用价值的步骤才拆分，并记录关系。历史版本和被替代的方法留在来源差异里，不混成未经验证的新方法。
- 仓库可读时 search 并比对真实已发布条目；不可读时继续本地去重，明确“团队查重未完成”。尚未核实成员身份或既有归属时只用本地草稿编号，不编造 owner 命名空间、正式版本或来源锁。
- 分别评估完整性、验证情况、适用范围与分享边界，再归类为“可直接复用”“需要少量补齐”“项目专用参考”“暂不建议共享”。完整但未经业务验证的条目不能标“可直接复用”，应说明需要何种试用。
- 上传优先级说明实际依据：可覆盖的常见工作、独立可复用程度、材料/证据成熟度、补齐成本。缺少使用频率或收益证据写未知，不编造分数、节省小时数或成功率。

## 4. 为每项能力生成详细中文说明

说明面向未参与原任务的策划，至少包含：

1. **名称、类型与业务问题：** 分享什么，用一句中文说明解决什么。
2. **适用与不适用：** 人群、场景、项目条件、明确边界。
3. **准备与输入：** 需要提供的材料、字段、格式及获取方式。
4. **完整步骤：** 每步目的、具体动作、工具/文件衔接、检查依据；操作顺序不能只列工具名。
5. **产物与验收：** 输出形态、保存位置的约定、应核查什么、何时算失败。
6. **脱敏示例：** 输入、关键步骤与预期输出；合成示例标明合成，不冒充真实实绩。
7. **依赖、环境、权限与副作用：** 必要文件/能力/外部工具，是否写文件、修改原稿或调用服务。
8. **实际验证与未验证：** 分别记录证据和覆盖范围；仅源码检查、命令成功或生成报告不等于业务通过。
9. **来源、作者与演变：** 本地对应文件和依据，可靠的原作者/版本信息、改编差异；未知写未提供。
10. **踩坑、限制与异常处理：** 发生条件、证据、调整方法与复用时的注意事项；不得从文件名猜出复盘。
11. **待补项与推荐状态：** 具体缺什么，怎么补，是否推荐投稿及原因。

详细说明不是把整份原文照抄。关键结论附可核对的文件/章节/工作表/行等依据。个人绝对路径和原始内容映射仅存在本地来源清单；未来共享版本须去掉无关个人信息，仍保留必要的非敏感来源标识。

## 5. 复制整理并交付实际文件

使用忽略的独立工作区；按 AI_OPERATIONS 的路径隔离规则建立新目录，不覆盖已有任务。原文件保持内容和位置，不移动、删除或执行。没有接入配置时，可在当前明确项目之外选择新的专用整理输出目录；先确认不落入待上传目录、不会被自动提交，再将位置告知用户。

建议本地结果结构（仅文件组织约定，不是新增 CLI）：

```text
<本次整理目录>/
  盘点总览.md
  文件盘点清单.csv
  能力目录.md
  来源映射.json
  待补与未检查清单.md
  建议上传清单.md
  整理进度.json
  草稿/
    <本地草稿编号>/
      README.md
      materials/
```

- 文件清单用标准 CSV 保留来源、检查状态、排除/阻断原因、关联草稿编号。来源映射可多对多；无法判断作者和版本时明确未知，不为形式完整而造信息。
- 草稿 README 写本节要求；materials 仅复制必要的、允许保存的材料及脱敏样例。没有足够分享依据的材料留在原处，来源清单登记即可，不先复制凭据或原始敏感业务资料。
- 有可信仓库配置和实际身份、且条目条件足够时，再按模板/schema 生成正式入库草稿并 validate；没有这些条件时交付普通能力说明和配套材料，标“尚未完成库格式校验”。不能伪造检查回执。
- 缺失规则或步骤保持待补，不臆造，也不通过自动运行未知代码来补证据。仅整理任务不安装依赖、不执行生产变更、不重演副作用。

## 6. 分批完成和可继续整理

- 范围大时按目录或完整业务流程分批，优先高复用候选，同时保留完整待处理队列。每批记录已检查材料、新增/合并草稿、未检查项与后续位置；不以“示例整理完成”结束全量任务。
- 整理进度记录范围、排除规则、文件摘要/修改时间、当前批次和待处理队列。恢复时核对变化文件并重新检查，不直接沿用旧结论。敏感内容不放进进度日志。
- 总览分别统计：发现文件数、排除文件数、范围内待检查数、已完整检查数、部分检查数、不可读取数、未开始数；范围内总数须能与状态分项对应。候选能力数与文件数分别计算，不把一文件当一能力。
- 只有队列已完成且统计一致才称盘点结束；部分检查或不可读取仍明确列为未验证。因工具、权限或时间无法完成时交付真实完成部分及继续记录，不说“全部检查通过”。

## 7. 上传与完成标准

本流程默认交付本地结果。用户明确“上传这些”后，确定已选条目，执行 AI_OPERATIONS 的中文说明、查重、完整包/出站检查、真实身份归属和 propose；不把整份本地来源清单或未选材料打包上传。保留版本、依赖、改编来源与实际回执。

完成时用中文报告实际覆盖范围、文件和能力数量、各成熟度分类、建议优先处理项、未检查/待补事项，以及本地结果位置。不要只输出建议；应有真实总览、清单、逐项说明与草稿。没有投稿不说已上传，待审核不说已入库，材料整理完成不等于业务验证。
