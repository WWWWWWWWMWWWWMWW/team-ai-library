# 策划团队能力库：本地网页设计与实施规划

状态：**已按用户确认的方案完成首版本地实现**。本文件保留设计与落地安排；实际使用见 [网页说明](LOCAL_WEB.md)，已执行的验证及边界见 [验收记录](LOCAL_WEB_VERIFICATION.md)。

## 1. 目标与已确认现状

**已确认：** 团队以策划自然语言为任务入口，AI 处理接入、整理、下载、复用、投稿和 Git。网页是可选的浏览与任务交接入口，策划也能直接对 AI 说需求，不强制先选技能。

**已确认：** [现有目录](CATALOG.md) 与 [机器索引](catalog.json) 来自同一共享快照，含具体版本、范围、依赖、来源与验证状态；当前六项共享内容为内置示例，真实业务未验证。当前仍仅所有者试用，多人权限尚未开放。

**建议：** 生成一个可双击打开的本地 HTML。首版不用后台、数据库、网页账号系统或在线模型调用；数据与必要说明随页面生成。主要体验是：找得到、看得懂、能交给自己的 AI 做。

**已验证：** 本机 Chrome 实际文件页面通过搜索、详情、复制与备用路径等 19 项验收，Safari 已确认打开、搜索、详情与正常复制粘贴回读；跨系统和 Safari 异常备用路径仍未验证。具体范围见验收记录。

## 2. 页面分工：一个文件、三个主要视图

| 视图 | 用户目标 | 首要内容 | 主要动作 |

## 3. 首页与搜索的详细设计

### 列表信息

默认展示紧凑列表，桌面每行一项，以方便比较工作流和阅读中文说明。每项只展示：中文名称、一句话用途、输入与产物、能力类型、选定版本、推荐标记、验证状态、查看按钮。原始 ID、摘要和提交号放详情的来源区域，避免用户先面对 Git 术语。

- 名称与用途采用真实元数据；摘要不足时补显示声明的输入产物，不编造功能或收益。
- 内置示例明确标“示例内容”；推荐与业务验证用两种独立标记，不能把“推荐”画成“已验证”。
- 常规列表按能力 ID 合并展示，版本在详情中选择；能力数与版本数分别计数。
- 无明确推荐版本时显示“尚无推荐版本”，不得自动选版本号最大的版本作为推荐。
- 已停用条目默认不参与普通使用列表，可通过“包含历史和停用版本”查看；已撤回、作废或依赖停用的版本不提供普通使用指令。

### 搜索规则（首版）

本地关键词检索，覆盖名称、用途、真实标签与别名、输入产物、适用范围、已打包的版本说明。支持中文输入和多个词；先完成输入法组合，再更新结果。按名称/别名精确匹配、用途匹配、范围/说明匹配排序，显示匹配出处，不能把限制说明里的命中包装成适用推荐。

- 不宣称已具备模型语义搜索。没有相关材料时显示真实空结果，不补造条目。
- 结果须对应具体能力和版本；只命中历史版本时标“匹配历史版本”，点击后打开该版本，状态仍按该版本显示。
- 查询改变后保留分类筛选；有筛选导致无结果时提供“清除筛选”。
- 首版不显示热度、使用次数、最近上传排序等无来源指标。默认排序只使用确定的内容与匹配信息。
- 场景快捷词由真实标签/别名生成，不摆放没有内容支持的“热门场景”。

### 空结果文案

“当前目录没有匹配内容。”下面给出“清除筛选”“让 AI 帮我查找或整理”。后者复制本次需求，让 AI 查询真实团队库并判断现有能力是否适用；依然没找到时可整理本地经验，不自动上传。

## 4. 能力详情：先判断是否适用，再看完整方法

桌面从右侧打开约 600px 宽抽屉，保持搜索结果与筛选上下文；小屏改为全屏详情。顶部提供关闭、中文名称、能力类型、版本选择与独立状态标记。

内容顺序：

1. **解决什么问题。** 用途摘要；需要提供什么；能得到什么。
2. **适用与限制。** 场景、前提和明确不适用条件。
3. **如何使用。** 具体版本 README 和可安全展示的文本入口；保留原方法，不通过网页重新发明步骤。
4. **使用前准备。** 团队能力依赖、外部工具、环境和权限；能点开本快照中的明确依赖版本。
5. **验证与风险。** 实际记录覆盖的业务、环境、工具、日期和证据；失败与未验证部分清楚列出。
6. **本版变化与来源。** 原作者、改编关系、完整材料标识与历史版本；未提供的变化说明写未提供。

底部固定两个动作：主按钮“复制使用指令给 AI”；次按钮“让 AI 保存这项能力”。临时使用与长期材料安装分别说明，不能把材料安装说成原生 Skill 已注册。

- 指令包含真实仓库、准确 ID 与明确版本、用户当前目标，以及按规则核对状态、材料和依赖后实际执行的要求。
- 用户可写一句“我这次要做什么”，不是必须填完整表单。未填时由 AI 在对话里补充必要业务输入。
- 页面复制的是任务指令，不代表 AI 已运行、文件已下载或任务已完成。成功文案只显示“已复制，粘贴给你的 AI 即可”。
- 版本无推荐时必须选择明确版本；停用版本的主动作改为“让 AI 查明停用原因和安全版本”，不生成普通复用指令。
- 来自旧版、另一环境或不匹配材料摘要的验证不继承；有通过与失败记录时分别展示范围，不做全局“已验证”标记。
- 能力 ID/版本可写进 URL 片段用于定位；具体业务任务原文不进入 URL、共享 HTML 或默认持久存储。

## 5. 沉淀能力：三个动作，不做复杂上传表单

| 入口 | 文案 | AI 应做的事 |
|---|---|---|
| 盘点我的 Codex | 自动整理我积累的技能和方法 | 自动定位明确的 Codex 素材，完整盘点，分批提炼中文草稿、来源和待补项；先本地整理 |
| 整理指定资料 | 把项目资料整理成可复用能力 | 使用当前明确的项目或用户指定资料；无法确定范围时识别候选供选择，不先索要手写完整路径 |
| 分享本次成果 | 把这次做法整理后分享到团队 | 提炼明确授权的成果，脱敏、补齐说明、校验、创建可追溯请求，自动检查通过后入库 |

每个入口显示一段简短解释和可复制任务指令，复杂规则由 AI 从库内指南读取。首次接入未完成时指令包含接入检查；仓库或新版指南不可读时，本地整理仍能继续，不能假称完成团队校验。

首版没有网页拖文件、批量读取全盘、直接执行脚本、浏览器安装 Skill 或一键合并。资料选择和真正上传交由具备文件与终端能力的 AI，网页辅助选择目标和说明。

### 处理中区域

展示生成时的请求编号、材料类型、涉及条目与“处理中快照”标记。提供“查看平台请求”和“让 AI 核对进度”。维护/治理 PR 与普通能力投稿、撤回 issue 不混用查询方式；AI 根据真实请求形式选工具。

网页不凭关闭请求就显示入库、撤回或恢复生效。只有平台与共享实际材料核实后，下一次生成的数据才可改变对应状态。

## 6. 视觉与组件规格

**建议风格：安静、清晰的团队资料书架。** 暖白底、深色中文文字、墨绿主要动作、细分隔线。以内容阅读为主，减少装饰图、大横幅和渐变；状态信息使用文字配合颜色。

| 项目 | 建议值 |
|---|---|
| 页面背景 / 内容面板 | `#F7F7F2` / `#FFFFFF` |
| 主文字 / 次级文字 | `#142A26` / `#52645F` |
| 主动作 | `#17624C`，白色按钮文字 |
| 分隔线 | `#D7DED8` |
| 未验证 | 文字 `#835B0C`、浅底 `#FFF4DD` |
| 失败/停用 | 文字 `#A43232`、浅底 `#FFF1EF`，同时写明状态 |
| 页面标题 / 分区标题 / 正文 / 辅助 | 26 / 20 / 15 / 13px；正文行高约 1.65 |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32px |
| 输入与按钮 | 高度至少 44px；有明显焦点边框 |
| 面板 / 按钮圆角 | 12 / 8px；阴影只用于抽屉和浮层 |
| 桌面布局 | 侧栏约 208px，主区弹性宽度，常规内边距 24px |

字体优先采用本机中文界面字体（PingFang SC / Microsoft YaHei 等，缺失时系统回退），标识和代码用本机等宽字体。备选是宋体标题搭配界面正文，增强资料阅读感；首版不额外下载字体。具体字体可用性与最终视觉仍需实际浏览器检查。

- 960px 以下收起侧栏为分类切换；680px 以下单列和全屏详情，主动作仍可见。
- 支持键盘 Tab、Enter、Esc，打开详情后焦点进入抽屉，关闭后回到原列表项；背景不可误操作。
- 搜索输入有可读标签；状态变化有文字提示；控件焦点不能只靠颜色。
- 正文与主要控件文字对比度以至少 4.5:1 为实现验收目标；本方案的主要颜色组合已用计算方式核对，最终页面仍需验证。[W3C：最低文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)
- 只做短暂的面板过渡，不做持续动画；尊重系统减少动态效果设置。

## 7. 本地运行与数据结构

### 建议架构

```mermaid
flowchart LR
  A[已批准共享 Git 快照] --> B[现有目录生成器]
  B --> C[中文目录与机器索引]
  B --> D[建议新增：打包安全文本说明]
  C --> E[单文件本地 HTML]
  D --> E
  E --> F[本地浏览 搜索 查看]
  F --> G[复制任务指令]
  G --> H[用户自己的 AI]
  H --> I[实时权限 状态 依赖检查]
  I --> J[下载复用或处理中投稿]
```

当前生成器同时输出 Markdown、JSON 与自包含 HTML；正文来自同一经核对的共享快照。

建议新增 `docs/local-library.html` 作为生成产物，样式、交互与目录数据全部内嵌。已批准版本的 README 与适合展示的文本入口从同一固定快照读取，并沿用材料完整性检查；大型二进制和脚本不打进可执行网页，交给 AI 按锁定版本取完整材料。

不要依赖网页 fetch 本机旁边的 JSON 或说明文件。文件来源行为存在浏览器差异，本地文件互读可能遇到同源限制；因此选择内嵌方案。[MDN：同源策略与本地文件](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Same-origin_policy)

复制操作先尝试浏览器支持的文本写入；只有成功后提示已复制。失败时打开可选中文字框，提供“全选”并说明用系统快捷键复制，不反复要求开权限。剪贴板 API 有安全上下文和用户交互要求，浏览器实现也有差异，需分别验收。[MDN：Clipboard API](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard_API)

### 同步与状态

- 双击页面可离线浏览嵌入的内容；离线查看不取得新增执行、安装、投稿或发布权限。
- 页面显示生成时间、内容来源与“本地快照”标识；生成时间不能冒充最后一次能力发布时间。
- “让 AI 更新目录”复制同步任务；真正更新要由 AI 在保留本机修改的前提下取得已批准共享内容、重新生成，再让用户重开页面。浏览器刷新只重读当前 HTML。
- 新生成失败时保留最后一份完整 HTML，错误报告给 AI；不能输出缺材料的页面冒充同步成功。
- 页面不读取密码、令牌、私人配置或原始聊天，不在本地表单保存具体业务原文；不加入统计上报、远程字体或远程脚本。
- 本地 HTML 会包含内部能力资料，浏览器文件本身不提供账户权限隔离。网页不会开放多人 Git 权限，分发范围仍按内部资料授权处理。
- 包内文本与未知 HTML 全部当数据展示；使用安全文本渲染、限制链接协议，JSON 嵌入时防止闭合 script 标签等内容变成页面脚本。

## 8. 关键决策记录（均为建议）

### ADR-W01：选择单文件网页

**背景：** 需要成员双击即可浏览，继续纯 Git 管理，减少安装与运维。

**决策建议：** 生成一个包含数据、样式与交互的 HTML，前端采用基础 HTML/CSS/JavaScript，复用 Python 生成链路。

**收益：** 无需跑服务、装前端依赖或维持数据库；页面与数据可审查并随 Git 分发。

**代价：** 更新后需要重新生成和打开；完整说明增加文件大小，实时状态不能由静态页证明。

**备选：** 本地只读 HTTP 服务可动态加载文件，但增加启动步骤；桌面壳可接近直接调用工具，但安装、签名和权限适配更重。先不采用，后续确有需要再扩展。

### ADR-W02：执行动作交给 AI

**背景：** 策划已有自己的 AI，真正操作需要文件访问、个人登录、版本锁定和权限核对。

**决策建议：** 网页生成带准确目标的任务指令；既有 AI 操作指南继续作为执行规则。

**收益：** 不在页面保存登录信息，继续沿用现有流程；普通策划不需要理解 Git。

**代价：** 首版要复制并粘贴到 AI；不能在页面实时显示任务进度。

**备选：** 后续通过经过验收的本地连接器交接任务，但不能先用一个按钮假称已执行。

### ADR-W03：目录与正文来自同一共享快照

**背景：** 当前工作分支和本机材料可能与共享版本不同。

**决策建议：** 从一个经核对的共享提交取得元数据、README、入口文本与依赖，不从随手编辑的当前目录混入说明。

**收益：** 版本、正文与来源一致；处理中请求不能混作共享能力。

**代价：** 每次真正更新需要仓库可读；离线只能看上次生成结果。

**备选：** 直接读取当前 checkout 更省步骤，但容易把未发布或改编材料当原版，首版不采用。

| P1：首页与详情 | 七种能力类型、四个使用场景、关键词搜索、具体版本、详情、依赖跳转、验证展示；能力卡片显示作者与来源 | 网页模板及交互；生成 docs/local-library.html | 打开首页即可看懂 Skill、工具、方法论等能力类型，也能按工作场景定位，状态与验证不混淆，双击和离线可浏览 |
| P2：任务交接 | 使用/材料保存指令、Codex盘点、整理投稿、更新指令、复制降级 | 生成器与可信提示词入口；相应用例 | 指令目标准确，复制成功反馈真实，用户无需填 Git 参数 |
| P3：实际验收 | 浏览器、键盘、窄屏、空数据、异常材料、旧快照 | 新增网页生成与交互测试；更新 README、AI 操作手册和网页使用说明 | 必需验收用例实际通过后，按授权提交并推送维护请求 |

建议首版完成 P0—P3 这一条完整使用链，再考虑收藏、阅读偏好、近期浏览等纯本机功能。网页直接操作 Git、内置聊天、评分排行榜、复杂账户系统、在线编辑器和自动合并暂不做。

只有承载浏览偏好的存储经兼容性与隐私检查后才加入；核心查询和任务交接不能依赖本地存储一定可用。页面生成错误、失效链接、素材未读、原生 Skill 导入均不得用界面成功提示掩盖。

## 10. 实施后的验收用例

以下是实施验收条件；实际执行范围、结果与未验证项记录在 [网页验收记录](LOCAL_WEB_VERIFICATION.md)，以该记录为准。

| 场景与前提 | 操作 | 必须达到的结果 |
|---|---|---|
| 单文件 HTML，网络断开 | 双击打开，在普通浏览器浏览与搜索 | 无需服务、远程字体/脚本或邻近文件请求；真实内容显示，快照状态明确 |
| 现有六项共享示例 | 搜“审策划案”“整理会议”“查漏项” | 定位对应能力与明确版本，示例与业务未验证标记可见 |
| 目录没有活动配置条目 | 搜“活动配置检查” | 真实空结果及交给 AI 的入口，不编造结果 |
| 一个能力多版本、没有推荐 | 打开详情并准备使用 | 不自动推荐最高版本；选择明确版本后才生成目标指令 |
| 撤回、作废或依赖停用的测试材料 | 切换该具体版本 | 状态清楚，普通使用按钮不可用，可交给 AI 查安全版本 |
| 精确验证记录与过期/不同摘要记录 | 查看验证区域 | 仅匹配本版记录被采用，并展示实际范围和失败记录 |
| 有处理中投稿与维护请求 | 浏览列表、进入处理中区 | 只在处理中区出现，不增加已共享能力数或显示已入库 |
| 剪贴板允许 / 拒绝两种情况 | 点击复制指令 | 成功才显示已复制；拒绝时有可选中全文的手动复制路径 |
| 刚盘点的个人草稿 | 使用“分享本次成果”指令 | 具体授权、中文说明和自动校验后创建请求，检查通过后自动入库 |
| 新指南在共享分支缺失 | 用 Codex 盘点指令交给 AI | 明确本地对象，继续本地整理，不要求业务项目路径或冒充团队校验 |
| 页面是旧快照 / 仓库不可读 | 点击更新并交给 AI | 不称同步成功，保留已有文件，指出读取阻断；F5不会被解释为同步Git |
| 任务文本含 script/HTML 等异常内容 | 渲染与搜索 | 只作文字展示，不执行、不请求远程资源，不逃出内嵌数据 |
| 桌面、小屏、只用键盘 | 搜索、开关抽屉、选择版本、复制 | 布局可读，主动作可达，焦点与键盘行为正确 |

首轮验证建议覆盖本机 Chrome 与 Safari 的实际 file:// 打开方式；其他成员操作系统和浏览器另行验收，不从本机结果外推。图标、颜色和“已复制”提示均须通过实际操作确认。
