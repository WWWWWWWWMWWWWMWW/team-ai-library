# 能力目录的生成与维护

策划从 [本地网页](local-library.html) 或 [能力总目录](CATALOG.md) 浏览，AI 可读 [同源机器索引](catalog.json)。根 README 提供入口。目录按技能、工作流、提示词、工具、案例、经验、研究资料分类，列明具体版本、用途、输入产物、范围、依赖、验证与使用入口。

## AI 自动生成

在本仓库根目录运行独立维护工具：

```sh
python3 tools/build_catalog.py --with-pending
```

工具读取 library.json，重新核对真实账号读取条件，并从配置的共享分支取得新的独立快照。不会把当前分支、未提交材料或投稿候选当成已入库能力；网络/权限失败时保留现有目录。此工具不是 library.py 的子命令，不执行能力脚本。

- 默认生成 docs/CATALOG.md、docs/catalog.json 和 docs/local-library.html；三份内容来自同一固定共享提交，记录来源，不写用户本机路径。
- 正式版本材料先检查实际文件清单与摘要、精确依赖和当前撤回/作废；材料异常时阻断目录更新。
- 推荐版本来自可信 state 的明确选择，不按版本号最高自动推荐；撤回、作废或依赖停用会阻断推荐展示。
- 验证记录只采用相同 ID、版本与材料摘要的记录，展示范围及失败/未验证状态。入库、推荐、下载或检查成功都不是业务验证。
- 加 --with-pending 才读取当前平台待审核请求，按实际文件区别能力投稿、维护和治理；请求内容只作导航，不能加入已入库能力数。查询失败明确显示“未能刷新”，不能显示“没有待审核”。不导出请求正文或聊天。
- 全量读取分页；读取某个请求文件后重新核对该请求的 head，变更则不把混合数据写入待审核目录。目录里的请求信息仍是生成时快照，后续可变化。
- 只能更新带生成标记的目录、机器索引和网页，已有手工文件保留并报告冲突。不要直接编辑生成文件的业务字段，应修正对应源条目，再重新生成。

网页内嵌同快照的安全文本说明，不加载旁边文件，也不执行脚本。网页单独可离线打开；每份文件原子替换，不承诺三份输出的事务一致性。HTML 替换失败时旧页面仍保有完整快照；使用方式与复制备用路径见 [网页说明](LOCAL_WEB.md)。

## 谁负责更新

维护者 AI 在能力入库、版本推荐或撤回治理生效后刷新目录，并验证链接、状态与实际来源，按已授权流程提交维护请求。普通上传者只投稿自己的条目，不改公共目录，减少公共文件冲突。

生成和提交可由 AI 自动处理；共享入库仍按审核规则决定。首版未实现服务器在每次合并后自动提交目录，不宣称已无人值守。维护者收到更新任务时可直接调用本工具完成生成与提交，策划不需要填目录表格。

## 时效与复用

静态目录可能落后于后续共享变更或请求状态。AI 用目录筛选候选后，仍调用 search/fetch/check-reuse；查询投稿用 status。不得只凭缓存目录批准执行、确认已发布或使用已停用版本。

本机整理草稿不会自动进入公共目录。本地整理按自己的能力目录交付；用户明确投稿后进入待审核请求区，核实共享发布后才进入已入库区。
