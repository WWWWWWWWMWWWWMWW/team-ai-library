# 冲突、撤回与恢复

## 并发和本地冲突

不同条目在刷新共享基线后最多自动重试两次，不强推。同 ID/版本不同内容或已发布目录被改写必须阻断；不能随意改号掩盖差异。

本机更新对比 base/local/upstream。双方改同文件、上游删除但本地修改、脚本/工作簿冲突，保留双方原件与候选，只让策划判断必要的业务差异。无冲突且已授权更新时才受控替换，留恢复副本。

## 普通误上传

成员说“撤回此版本”后，AI 创建平台治理 issue，记录 ID/版本/非敏感原因，返回已提交待处理。维护者 AI 从可信状态生成 state PR/MR，标记撤回、清除坏版推荐并检查依赖影响。审核合并并核实后才报告生效。

撤回保留旧版本材料和历史，停止通过库流程安装/复用。不能宣称已从所有成员机器删除。

## 有害版本恢复

撤回坏版→选择已核实安全旧版或发布修复版→重查完整依赖、范围与环境→保全本地修改并受控替换→实际试用并记录。

只修改状态/允许的发现元数据或新增版本；普通 revert 也不能删除或改写已发布 releases。保留其他成员后续投稿。能力恢复不自动撤销过去已造成的业务项目或远程改动，后者按具体项目另行处理。

## 敏感信息泄漏

不能拿普通撤回或删除文件当清除。涉及凭据先撤销/轮换，再由维护者和管理员按公司应急流程处理历史、引用、缓存及副本。普通客户端没有自动强推或历史重写按钮。

清理后记录非敏感作废范围与替代版本，重新取得干净快照，阻止旧历史重入。旧 SHA 可能不再可复现，应准确说明，不能把新包冒充旧版。

安装、更新、库流程复用前刷新撤回/作废状态；断网只浏览缓存/草稿。直接调用已经安装的 Skill、手工复制或离线副本无法由纯 Git 实时召回。演练只用隔离仓库和假凭据。
