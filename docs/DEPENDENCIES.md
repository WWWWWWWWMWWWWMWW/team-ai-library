# 版本、依赖与适用范围

每项能力有固定原作者命名空间/slug 的 ID 和独立 X.Y.Z；移交保留 ID，权限按当前可信 owner 判定。契约包括输入、输出、使用方式、工具和权限要求。兼容修正发 PATCH；兼容扩展发 MINOR；不兼容变化或扩大必要权限/副作用发 MAJOR。版本目录发布后不可改写，说明或材料改动也发新版本。meta 的发现信息可改但仍审核。

manifest 必填：

- entrypoints：从哪里开始使用。
- scope：inputs、outputs、includes、excludes。
- compatibility：OS、运行时、AI/目标工具和所需操作能力。
- effects：只读、本地生成、项目文件变更或远程写入。
- dependencies：同仓库精确 ID＋version＋manifest_sha256。
- files：本版 README/payload 的排序清单、大小和摘要；不含 manifest 自身。

所有依赖从同一固定快照取完整闭包，再查当前撤回/作废状态。缺项、循环、摘要不符、目标冲突不能自动选 latest。使用前核对根能力与传递依赖的**实际**文件摘要；本地修改不能冒充锁定原版或沿用原版验证。

外部运行依赖只记名称、来源、版本条件、用途及既有 lock 位置。凭据只记名字和用途，不记值。首版不自动求解版本范围或安装全部未知外部依赖。

用户任务有写入或安装授权才可相应操作；manifest 不能授予权限。工具 A 的验证不能外推工具 B；未覆盖的环境/业务输入明确标未验证。材料精确复现不保证模型输出一致。
